All of them were produced under the clean-room rule: ngspice was run as a black box and its source was never read.

## RC-lu-pivot: Frozen-pivot unrolled LU (garbage / NaN transients, card-order dependence)

Files: `RC-lu-pivot-proposal.patch`. Analyst confidence: **high**.

**Root cause.** The calibrator's first hypothesis is correct and the second is refuted. Simulator::from_netlist (rustspice-solver/src/simulator.rs:51-54) stamps the x=0, caps-open DC Jacobian and hands it to AdaptiveSparseSolver::compile (linear.rs:45), which calls UnrolledSymbolicLu::compile (rustspice-backend-cpu/src/jit.rs:65). That routine freezes the row permutation once: for each column it takes the lowest-degree row among all rows with |a_rk| >= 1e-3*colmax (jit.rs:134-146), so on diagonally dominant R/C meshes it picks small off-diagonal conductances instead of the diagonal (255 of 258 pivots off-diagonal on the 16x16 RC mesh). The numeric factorisation (jit.rs:347 factorize, the Cranelift body at ~jit.rs:549, factor_and_solve at jit.rs:683) never pivots numerically and never checks growth; it only tests |pivot|<1e-14 or non-finite x. Once the transient adds C/h or 2C/h to the node diagonals, each stage multiplies by about diag/offdiag: dense replica gives max|U| 6.2e20 (BDF1), 1.2e27 (trapezoid), 1.0e34 (half step), cond(A)=5.0, partial-pivot growth 1.0. The matrix is perfectly conditioned and the frozen order is the sole cause. The DC mesh decks fail the same way at compile-time values (multipliers 9e2..1e3 allowed by the 1e-3 threshold, backward error 1.5e-9..4.7e-8, error 6e-6..1.8e-5 V). The constant-h cache in transient.rs:150-153 is exonerated: it checks is_linear, step_method, |h-prev_h|<=1e-9*h and has_valid_factorization, and the first post-OP factorisation (no reuse yet) already has a 6e20 pivot.

**Patch.** Three files, diff relative to the pre-fix working tree of the module root. jit.rs: pivot threshold 1e-3 -> 0.1; keep the structural diagonal when |a_kk| >= 0.5*colmax (branch rows of V/L keep the min-degree choice); register structural zero entries in col_to_rows (fixes bogus SingularMatrix); abort symbolic elimination at 500k ops instead of running to completion; new UnrolledSymbolicLu::factors_are_stable (|l|<=1e4, |u|<=1e6*max|A|, finite). linear.rs: deterministic minimum-degree symmetric ordering for n>=32, applied as gather/scatter around the unrolled solver (restores sparsity lost by diagonal preference); stability monitor after every unrolled factorisation; on failure factor that matrix with a dense partial-pivoting LU (n<=48, new LinearSolverKind::DensePartialPivotLu) or faer, track where the cached factors live so solve_cached / solve_transpose_cached never read stale lu_buf, and demote permanently after repeated failures. main.rs: report a demotion in stats.solver_kind (A>B) and on stderr.

## RC-time-grid: Transient and DC-sweep grid (sliver last step, dropped last sweep point, first step, retry desync)

Files: `RC-time-grid-proposal.patch`, `RC-time-grid-proposal_dc_exact_grid.patch`. Analyst confidence: **high**.

**Root cause.** Three independent mechanisms, all confirmed by model and by running the frozen binary.

(1) tran-degenerate-last-step. crates/rustspice-solver/src/transient.rs, original lines 133-139 and the `t = t_next` updates, build the grid by repeated `t += h`. The loop guard is `while t < tstop - 1e-9*tstep`. The accumulated rounding error (about n*ulp(t)) exceeds the guard once there are a few thousand steps, so t ends short of tstop and `h = min(tstep, tstop - t)` appends a sliver step.
- acc_tr_final_time_sliver: t[10000] is 1.2997e-17 s short, guard 1e-17, sliver dt 1.298e-17 s.
- acc_tr_last_step_rc_mesh: 1.1435e-20 s short, guard 1e-20, sliver dt 1.145e-20 s.
- The garbage values (4.0e5 V on n1_1, 2.2e5 V on n0_2) come from the CraneliftJit static-pivot LU solving the h=1.1e-20 s system. A dense f64 partial-pivot solve of that system (cond 1.8e8, C/h about 1e8 S, not 1e32) returns the previous row to 1.1e-16. So the grid bug only exposes a separate linear-solver accuracy defect.

(2) dc-sweep-grid-drift. crates/rustspice-solver/src/nonlinear.rs solve_dc_sweep, original lines 372-381, uses `cur += step_signed` with guard `cur <= stop + 1e-12*|step|`. The accumulated drift (4.4e-15 at 5 V, from 0 to 5 in 1 mV steps) exceeds the guard (1e-15) after about 100 additions, so the last point is dropped. The row writer in crates/rustspice-cli/src/main.rs only dumps whatever the solver returns.

(3) fixed-step-accuracy, only the parts in scope.
- First step: transient.rs forces the whole first tstep to be one BDF-1 step. With a = tstep/tau = 0.1 that gives v1 = a/(1+a) = 0.0909 against exact 0.0947. A python recursion reproduces every frozen row to 1.2e-15.
- PULSE rounding: the `t <= td` test in evaluate_at (crates/rustspice-core/src/netlist.rs) sees the accumulated grid time, which lands on either side of td depending on rounding. For acc_tr_rc_pulse_zero_edge_pw (tstep 20p, k=50) the accumulated t is 1.0000000000000005e-9, above td, so the jump appears one step early. For tstep 2p, k=500, the accumulated t is 9.99999999999997e-10, below td. With k*tstep the two decks behave consistently.
- A third effect is retry grid desync. After a Newton retry the old loop kept the shifted grid, so rows carried off-grid times and extra rows. acc_tr_diode_clamp had 402 rows (expected 401) with off-grid times, and err 0.187 against the ngspice reference.
- Not fixed by this patch: the other fixed-step decks have no breakpoints or LTE.

**Patch.** proposal.patch (variant B, git-style, relative to the module root) applies cleanly with `git apply --check` on a pristine copy of the module. It touches transient.rs, nonlinear.rs and adds tests/time_grid.rs.

Transient (transient.rs):
- Integer-counted grid. Row k is at exactly k*tstep, with tol_q = 1e-9 + 4*eps*q steps.
- A tail below tol_q steps is merged into the last interval, whose row is stamped tstop, so there is no sliver. A genuine tail gets one shorter step.
- The first output interval is 16 equal BDF-1 sub-steps (STARTUP_SUBSTEPS) that are not recorded as rows, then trapezoid.
- A Newton retry now splits the step and re-synchronises on the grid point. Only grid rows are recorded, so rows are always exactly k*tstep.
- The linear LU-reuse fast path and the est_steps line are unchanged, so the resource-bomb decks behave as before.

DC sweep (nonlinear.rs):
- The point count is floor(|stop-start|/|step| + tol_q)+1, with the same tol_q.
- Abscissae keep the historical `cur += step` values, bit-identical to before and to ngspice's own values, so nothing existing can move.
- A NaN span or step keeps the empty sweep.

Alternative: proposal_dc_exact_grid.patch applies on top of proposal.patch and uses `start + k*step` instead (drift-free abscissae). It flips 2 passing decks (see regressions). Choose it only if those two deck tolerances are revised.

Other files: artifacts/rustspice-timegrid is the patched binary, and artifacts/report_patched_full_866.json is the full run.

**Decks it closes** (9): `acc_dc_grid_drift_down_diode`, `acc_dc_grid_drift_up_5v_1m`, `acc_tr_final_time_sliver`, `acc_tr_last_step_rc_mesh`, `acc_tr_rc_first_step_bdf1`, `acc_tr_diode_clamp`, `acc_tr_rc_sin_fc`, `acc_tr_rlc_q0p5`, `rob_hs_c_negative_growth`

If the bench engine's `npoints` check or a doc table cites the old sliver, the closures above need the 'doc update needed' entries from spec section 5."


## RC-newton-clamp: Newton voltage box, exponent clamp at 80, absolute residual criterion

Files: `RC-newton-clamp-proposal.patch`. Analyst confidence: **high**.

**Root cause.** Three independent mechanisms, each reproduced and each flipped by a control. (1) clamp-rail: crates/rustspice-solver/src/nonlinear.rs solve_in_place (about lines 119-141 and 193-195 of the original) projects every node voltage onto a box derived from the DC vsrc values: [vmin,vmax] for DC without isrc/vccs, otherwise [vmin-span, vmax+span] with span=max(vmax-vmin,5); transient uses the instantaneous source values. A solution outside the box can never zero the KCL residual, so Newton stagnates on the rail and returns ConvergenceFailure after 150 iterations. Trace of acc_dc_clamp_stacked_vsrc_diode shows clamp=[0,5], node 2 raw 10 V projected to 5 V every iteration, max_res=5. source stepping even scales the box down (clamp=[0,0.5]). Secondary finding: the box is load-bearing for MOSFET circuits, because eval_mosfets has no fetlim/limvds. The 50-stage CMOS chain t=0 operating point and acc_dc_mos_cascode_bias need it, and removing it outright regresses perf_med_cmos_chain_tran_50 (raw iterate 6.5e103 V) and acc_dc_mos_cascode_bias (Newton limit cycle). A fixed per-iteration trust region instead of the box also broke the cascode. (2) Predictor reference bug exposed once the box is gone (acc_tr_buck_converter regressed pass to fail_accuracy with the box off): transient.rs:218-223 and nonlinear.rs solve_dc_sweep call sync_device_voltages(topo,&x_predicted), so pnjlim's vold equals the extrapolated vd (+13.18 V at the buck switch-off edge) and Newton starts unlimited deep in the exponential. The old box masked it, because clamping x_new to -12 V made |vnew-vold|>2vt so pnjlim returned vcrit. (3) exp-argument-clamp: backend-cpu/src/simd.rs:149 clamps the diode exponent argument to +-80 while the conductance stays the unclamped slope. The current is flat and the Jacobian is inconsistent above vd=80*n*Vt=2.07 V. In the saturated region Newton moves exactly one Vt (0.025864917 V) per iteration, and pnjlim does not limit steps under 2vt. The 5 V direct-across-source deck converges to exp(80) with exit 0 (i=-5.5406e20 A vs the exact 9.0023e69 A). (4) abstol-absolute-residual: nonlinear.rs:151-158 and 177/242 compare max|r_i| with the absolute abstol=1e-12 A. The residual includes the rounding noise of the rhs terms ieq=id-gd*vd (about 4e4 in magnitude for the kA deck). The stall value 7.275957614183426e-12 equals math.ulp(gd*vd)=2^-37 exactly, and the 1 MA deck stalls at 2^-29. The iterate is a floating-point fixed point (max_step=0) that can never meet 1e-12. Non-monotone in current (rounding lottery): the baseline fails at 1000/5000/8000 A and passes at 100000 A.

**Patch.** Unified diff, module-root relative (a/ b/ prefixes, patch -p1, dry-run applies cleanly to the original tree). It touches 5 files. (a) simd.rs: diode_exp() evaluates the exact exponential up to DIODE_EXP_ARG_MAX=600 and continues linearly with matched value and slope above it (replaces clamp(-80,80); cond/did_dn use the consistent slope; unit test added). (b) nonlinear.rs: after an accepted iterate, check_diode_exponent_range() refuses with the new SimError::DeviceRangeExceeded, using the junction voltage read from x, so the continuation can never be returned silently. (c) nonlinear.rs: the KCL criterion becomes |r_i| <= abstol + res_reltol*s_i with s_i=|rhs_i|+sum|J_ij x_j| (res_reltol=1e-12, fused spmv_with_magnitude pass); the reported max_residual stays the raw max|r|. (d) nonlinear.rs: the legacy source-derived box is kept as first attempt but is released for the rest of the solve after box_release_iters=16 consecutive binding iterations, so rails, rectifier, charge-pump and current-driven nodes become reachable while MOSFET circuits keep their stabiliser. (e) transient.rs and nonlinear.rs (sweep): after the predictor, sync_device_voltages(prev_x) instead of the extrapolated x, so pnjlim limits relative to the last converged point. (f) error.rs: new variant DeviceRangeExceeded. The module itself was not touched.

**Decks it closes** (26): `acc_dc_clamp_isrc_node_diode`, `acc_dc_clamp_negative_rail_diode`, `acc_dc_clamp_stacked_vsrc_diode`, `acc_tr_boost_5v`, `acc_tr_charge_pump`, `acc_tr_diode_bridge`, `acc_tr_diode_halfwave`, `rob_cv_clamp_highside_gate_58v`, `rob_cv_clamp_isrc_100v_node`, `rob_cv_clamp_isrc_mos_gate`, `rob_cv_clamp_neg_rail`, `rob_cv_clamp_stack_5v5v`, `rob_cv_clamp_vccs_50v_node`, `rob_cv_rect_bridge_rs_10v_tran`, `rob_cv_rect_fullwave_ct_tran`, `rob_cv_rect_halfwave_10v_tran`, `rob_cv_diode_direct_5v_op`, `acc_dc_diode_fwd_kiloamp`, `rob_cv_diode_fwd_kiloamp_op`, `rob_cv_diode_fwd_sweep_kiloamp_dc`, `rob_cv_diode_string_100_1kv_op`, `rob_cv_diode_string_300_1kv_op`, `rob_cv_scale_1ma_diode_mohm_op`, `rob_hs_diode_forward_1kv_1ohm`, `acc_tr_diode_clamp`, `rob_cv_boost_converter_tran`

In crates/rustspice-core/src/netlist.rs (module working tree) parse_netlist (582-690), parse_statement (997-1302), parse_waveform (912-995), parse_model_card (823-910), extract_key_values (795-821) and parse_spice_number (10-71) return only values or Err, so there is nowhere to say 'I ignored this'. Dot cards the match does not know fall into a no-op arm (1088-1090), so .include/.lib/.options/.temp/.measure and the like vanish. .model, .param and instance key=value lists only ever look up the keys the code already knows, so every other key is never inspected (795-910). parse_waveform ends in a DC fallthrough (994), so PWL, EXP, SFFM and misspelled forms become a constant. parse_spice_number accepts any numeric prefix and ignores the trailing text (48-49) and reads suffix x as meg (52), and a {..} expression is cut at its first blank by the whitespace tokenizer (expr-truncation). The first line is handled as a title only conditionally (582-596), so a blank or dot-led line 1 becomes a card. .dc (1009-1041, soa.rs:297 set_source_dc_value via nonlinear.rs:392) overwrites the source waveform in place and never restores it. .tran tstart/tmax (1061-1067), element ic= and .ic (1075-1087; soa.rs:540,603) are parsed but not applied as SPICE does, and the m multiplier is dropped (soa.rs:660 uses only d.area). The only loud paths are a few explicit Err returns (unsupported device 1294-1299, bad number), and their messages are sometimes misattributed. The CLI (crates/rustspice-cli/src/main.rs:262-265 read and parse, 297/363 analysis loop) consumes the parse result with no way to surface reader findings, and the bench engine classifies runs by exit code and raw file only. Hypothesis tested: a generic, non-behaviour-changing audit layer (Diagnostic list on Netlist + stderr rendering) can make these decks loud. Result: confirmed for visibility (164 of 168 silent-slug decks that were silent now warn), refuted as a closer of gaps: no deck changes status, because a warning does not change the numeric answer or the exit code.

**Patch.** 2341-line unified diff (patch -p1 from the module root; applies cleanly to a pristine copy and reproduces the private tree byte for byte; git apply --check also passes against the module, which was not modified). New crates/rustspice-core/src/diag.rs: Diagnostic{line, severity Warning|Note, code, message}, bounded DiagSink (at most 100 diagnostics per deck, 400 bytes per message, de-duplicated, whole-deck items last), allocation-free number audit (expression truncation, x suffix, unbalanced braces, overflow), catalog of ignored dot cards, audits for .options/.temp/.tran/.dc/.ic, model-parameter and instance-parameter audits, source-waveform audit, 8 unit tests. netlist.rs: Netlist.diagnostics (serde default), parse_statement/parse_model_card/extract_key_values take a sink and audit alongside the legacy parsing (the parsed circuit is never changed), deferred severities for ic/uic/DC-with-waveform, title-line, .control, orphan '+' and unterminated .subckt findings. lib.rs exports the types. CLI: prints 'warning[code]: line N: message' to stderr plus a summary line, a runtime dc-sweep warning when a later analysis follows a .dc, and opt-in --strict (exit 1 on any warning); default exit codes unchanged.
